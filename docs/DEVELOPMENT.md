# 開発構成

```text
src/ds2port/      GUI・SSH・転送・プロファイル互換修正
profiles/        対応ゲーム、原本/修正後のSHA-256、保持するセーブフォルダー
runtime/native/ AArch64の画面・入力・MIDI・音量処理、Win32フォント互換DLL
runtime/templates/ ゲームごとに配置先を埋める設定
runtime/install_remote.py  本体上の検証・バックアップ・配置・ロールバック
scripts/        依存取得、ビルド、配布候補の作成
tests/          アーカイブ安全性・互換修正・原本保持とWin32検証ソース
bld/            キャッシュ・生成バイナリ・検証ログ（Git対象外）
```

## タイトルの追加

通常はプロファイル追加なしでゲームフォルダーとEXEを指定します。`detect_game` が32bit PEを検証し、既知の原本は固有プロファイル、それ以外は共通ランタイムの設定を生成します。EXEが複数ある場合は明示選択が必要です。

共通マウス修正はPEのSetWindowsHookExAインポートを解決し、`hMod=NULL / callback / WH_MOUSE / call` の命令列と実行セクション内のcallbackを照合します。実行セクション末尾のゼロ埋め領域に、元のthread-IDスタックスロットを現在のスレッドIDへ置き換えるコードを追加します。末尾に23バイト分の空きが足りない場合は、ゼロ埋めされた既存ヘッダー領域に専用の実行セクション `.dsport` を追加します。既存セクションやファイル末尾の付加データは移動しません。退避するcallbackアドレスの再配置エントリーも移し、再配置時に元のジャンプ命令が壊れないようにします。安全なセクションヘッダー枠もない場合は転送を止めます。JUMP3の固定アドレスを別ゲームへ流用しません。

共通フォント修正は `CreateFontA` / `CreateFontIndirectA` と `GetTextMetricsA` の近接呼び出し、高さ・最大幅の参照、packed fontへの幅格納命令を照合します。一致する呼び出しだけをWin32の `dsfont.dll` へ向けます。既存インポート記述子とIATを保持して専用インポートを追加し、6バイトの呼び出し命令と再配置位置を維持します。フォント用 `.dsport` はローダーがIATを書ける属性にします。

DLLは横書き・固定ピッチ・SHIFTJISのフォント要求を対象に、要求平均幅と実測平均幅の差を最大4回補正します。同じフォント名・文字セット・実測高さを保持する候補だけを採用します。文字送りに使われる最大幅は、実際の描画DCで測った全角「あ」の送り幅へ置き換えます。全Unicode範囲の最大字形を旧エンジンの全角セル幅として使うことを避けます。高さやTextOutは変更しません。Win9x全般のフォントマッパーを再現するものではありません。固定の90%指定やJUMP3の固定アドレス変更は不要になりました。

`scripts/build-windows.ps1` は `build-font-shim.ps1` でMinGWのWin32 DLLを `bld/win32/dsfont.dll` に作り、GUI・CLIへ同梱します。転送ペイロードから各prefixのsyswow64へ配置し、共有ランタイムの全量更新を避けます。DLLはゲーム別のOverlayFS上位層に保持されます。`tests/font-compat32.c` はフォントの平均幅・全角送り・高さと対象外APIの通過を検査します。

PCMとFMは同じ48kHz dmix・本体音量フィルターを共有します。PCMだけALSA routeで係数0.7を適用し、FM音源プロセスには別の `asound-fm.conf` を指定します。`tests/audio-balance.c` による同じ振幅の入力で、ファイル出力のPCM/FM振幅比0.700を検査できます。


固有の修正が必要な場合だけプロファイルを追加し、対象版の原本ハッシュ、実行ファイル名、保持するセーブを指定します。修正後ハッシュも照合します。

画面・文字・音・操作・保存を実機で確認してから対応表へ追加します。Win95ゲームがすべて同じランタイム設定で動くという前提は置いていません。

## CLI

パスワードは `DS2PORT_SSH_PASSWORD` 環境変数、または秘密鍵で渡します。引数やログへ平文で記録しません。

```powershell
DS2PortCLI.exe inspect --host 192.0.2.10 --user root --key C:\Keys\device_key
DS2PortCLI.exe install --host 192.0.2.10 --source D:\JUMP3 --runtime runtime.tar.gz --key C:\Keys\device_key
DS2PortCLI.exe install --host 192.0.2.10 --source D:\FLOAT --executable FLOAT.EXE --runtime runtime.tar.gz --key C:\Keys\device_key
```

初回接続は表示されたフィンガープリントを確認し、`--accept-new-host-key` を付けて鍵を登録します。登録済み鍵の不一致は自動承認しません。

`--port-id jump3-tool-test` で既存のjump3とは別の場所へ検証用配置を作れます。起動には同じdisplay 93と本体入力を使用するため、同時実行はできません。テスト完了後はその配置だけを明示的に削除します。

## 実装上の注意

- SFTP非搭載の本体に対応するため、転送はSSHのファイルストリームを使用します。
- FAT領域にWineを展開せず、リンクを保持できるext4で展開・検証します。
- 保存領域が読み取り専用の場合は配置を開始しません。
- 更新時、Wine・native・licensesは既存ツリーとファイル内容・モード・リンク先・構成が一致すれば再利用します。変更があるツリーだけをバックアップして置換します。
- ダウンロード・転送後にハッシュを検証し、原本ハッシュやインポート・命令列の照合に失敗するEXEへ固定アドレスの修正を流用しません。
- インストール中は別プロセスからの同時転送をロックします。
- Win32検証プログラムは処理を完了してもUnixに137を返すことがあるため、マーカー出力も照合します。
- 入力は通常の押下・解放です。Win95のDLLなしグローバルWH_MOUSE登録は、Wineで失敗するためゲームスレッドへ限定します。
- fbbridgeはevdevを排他取得しません。PlumOSの電源メニューはfb0を開くプロセスをSIGSTOPするため、排他取得すると停止中もコントローラーを保持し、メニュー操作を妨げます。power-menu-overlay.lockとSIGCONTを監視し、メニュー中の入力・描画を抑止し、復帰時に溜まったイベントとマウス・キー・移動状態をリセットします。
- 初回はwinebootでprefixを作成した後、wineserverを停止してから専用prefixの日本語設定を更新します。Box64上のregeditの終了コードやレジストリ保存時刻へ依存しません。無関係な設定を保持し、変更前のレジストリもprefix内へ保存します。PCのWindowsレジストリは変更しません。
- `LC_ALL=ja_JP.UTF-8` を本ゲームの起動環境へ設定します。Wine 10の[ロケール初期化](https://github.com/wine-mirror/wine/blob/wine-10.0/dlls/ntdll/unix/env.c)はCロケール時にLC_ALLを参照します。本体に日本語glibcロケールがない構成でも、Win32検査でGetACP=932、システム・ユーザーLCID=1041を確認しています。

## 入力モードの実装

fbbridgeがLinux uinputに4ボタン・2軸の仮想Joypadを作成し、L2で物理ボタンの送信先を切り替えます。Joypadはマウスモードでも起動前から存在し、起動時だけ列挙するゲームにも対応します。マウスモードではJoypadを中立に保ちます。

PlumOSにはudevデーモンがないため、作成した仮想デバイスだけに `/run/udev/data` の分類情報を作り、終了時に削除します。WinebusはSDL経路を無効化し、udevの直接列挙を使用します。これにより物理10ボタンのパッドと仮想4ボタンの二重入力を避けます。物理デバイスの分類情報は変更しません。ゲーム開始前にfbbridgeの準備完了を待ちます。

`port/input-mode` の `mouse` / `joypad` が起動時設定です。転送GUI・CLIから指定します。切替時と電源メニュー復帰時にマウス・キー・Joypadの状態を解放します。evdevの排他取得は行いません。

`tests/joy32.c` はWinMMでのデバイス列挙と押下・解放・軸値を確認する所有ゲーム非依存の診断です。`i686-w64-mingw32-gcc -O2 tests/joy32.c -o bld/joy32.exe -lwinmm` で作成できます。`tests/virtual-joypad-probe.c` はLinux側のデバイス作成検査です。通常のfbbridgeと同時に仮想デバイスを作らず、診断後は必ず終了してください。

## ランタイム共有と空き容量

`/mnt/plumos/ports-runtime/.shared/runtime-<アーカイブSHA256>` が版ごとの共有キャッシュです。ファイルのSHA-256・モードと、ディレクトリ・リンク構成を検査します。旧配置から同一ファイルを集めて構築でき、既存キャッシュがあればアーカイブの再転送・全量展開を省略します。初回に一致する版がなければ従来どおりアーカイブを展開・検証してキャッシュを作ります。新しい版でも既存ファイルと一致する内容は再利用します。

Wine・native・licensesとBox64等の補助ファイルはハードリンクで共有します。管理する更新は一時ファイル／ディレクトリの置換で行い、共有ファイルの直接上書きはしません。配布物に残ったビルドユーザーの所有者IDはrootへ統一します。レジストリ・ゲーム・セーブは共有しません。

`prefix_storage.py` はWineのx86_64-windowsをsystem32、i386-windowsをsyswow64の読み取り元とするOverlayFSを構成します。ゲーム別の `prefix-overlays/<名前>/upper` と `work` を使用し、共有元は `prefix-storage.json` で版ごとに固定します。内容・モード・所有者・拡張属性が一致する通常ファイルだけを、アンマウント中にprivate層から取り除きます。独自DLL・whiteout・opaqueディレクトリ・異なる属性は保持します。共有元のキャッシュは参照がある限り削除しないでください。

初回Winebootは通常のprivate環境を作り、停止して日本語設定を適用した後にDLL共有へ切り替えます。起動時には状態からマウントし、終了時にはwineserverの停止を待ってアンマウントします。操作はゲーム別のflockで排他し、転送ロックと表示ロックも照合します。OverlayFSが利用できない本体では通常のprivate環境を維持します。

生成設定・フォント・Box64の参照先は `R/port`、ログは `R/logs`、導入記録は `R/installed.json` です。FATの `P` には主にゲームとセーブを置き、Portsの起動スクリプトからext4側へ移ります。旧配置の設定は移行時に残しますが、新版の起動では使用しません。

容量判定は、キャッシュがあればランタイムのアーカイブ・展開分を除きます。新規／不完全prefixには640MiBまでの増加分を予約し、日本語設定済みprefixには再予約しません。ゲーム一時領域と160MiBの余裕も加算します。初回Winebootの一時的な増加分を無視して容量チェックを通す方式にはしていません。

環境のバックアップは停止中に行い、prefixだけでなくprefix-overlays、prefix-storage.json、参照する共有キャッシュも含めます。表示用system32/syswow64はアンマウント中には空になります。通常のPortsランチャーを通して起動してください。

## 転送ツールの接続情報

GUIは終了時にIPアドレス・SSHユーザーとパスワード保存の選択を `%LOCALAPPDATA%\ds2port-v90s\settings.json` へ保存します。保存先はEXEのフォルダーとは別なので、ツールの更新後も引き継ぎます。パスワードは既定で保存せず、チェックした場合だけJSONへ平文で保存します。チェックを外して終了すると保存済みパスワードも取り除きます。秘密鍵の内容は保存しません。

設定は一時ファイルへ書き出してから置き換えます。設定が存在しない場合や読めない場合は初期値で起動し、終了時の保存に失敗した場合は画面へ通知します。転送中の終了操作では保存・終了しません。
