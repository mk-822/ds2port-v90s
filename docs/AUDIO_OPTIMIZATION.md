# DirectSound音声最適化の試験記録

v0.1.5の転送ツールは、全タイトル共通で軽量化したWine 10のDirectSoundを使用します。ゲーム固有の同時発音数制限や再生速度の変更は行いません。

## 対象と変更

GEO3で全体魔法の効果音が重なると音飛びと進行の引っかかりが発生するとの報告を受け、Wine 10のDirectSoundを調査しました。原本には16枠の音声管理があり、無制限の発音を前提とする修正は採用していません。

`runtime/patches/wine10-dsound-optimized.patch` は公式wine-10.0のソースへ適用する修正です。

- 浮動小数点ミキシングとFIR内積のSSE処理。
- FIR係数を周波数比の周期ごとにキャッシュ。各バッファは最大1MiB、周期1024までとし、対象外や確保失敗では従来処理を使用。
- 周波数変更時はキーで再構築し、参照位相を周期内へ正規化します。バッファ複製時はキャッシュ所有権を分離し、解放時に破棄します。
- 標準8/16bit PCM・float入力と通常のモノラル／ステレオ出力で、サンプルごとの間接関数呼び出しを省略。他の変換は従来経路を維持。

FIRのフィルター係数表・タップ数・48kHzの物理出力を維持します。係数計算の正規化と加算順序が変わるため、ビット単位で同じ出力になるものではありません。線形補間への置換や同時発音数削減は、この修正には含みません。

## 実機比較（2026-10-25）

所有ゲームを使用しないWin32診断で8bitモノラル音を連続再生し、位置取得・再生位置変更・再生操作を20ms周期で行いました。CPUはプロセス全スレッドの合計で、100%が1コア分です。ゲームの画面描画やBGMを含む測定ではありません。

| 条件 | 標準版CPU | 最適化版CPU | 最適化版の再生API最大待ち |
| --- | ---: | ---: | ---: |
| 8音、11,025Hz、816MHz | 約105%（飽和） | 62.9% | 1.14ms |
| 16音、11,025Hz、1.8GHz | 約104%（飽和） | 68.0% | 0.45ms |

CPUガバナーは比較測定の間だけ変更し、元へ戻しました。ゲーム用のCPU設定は変更していません。標準版は飽和しているため、この比率だけで厳密な処理速度の向上率を求めることはできません。

SIMD化だけの比較では改善を確認できませんでした。FIR係数キャッシュに加え、PCM読み書きの間接呼び出し削減を組み合わせた構成で改善を確認しました。PCM70%の音量経路を外しても標準版の飽和が続くため、音量調整単独が主因とは考えていません。

配布用ビルドの再検査（2026-10-26、1.8GHz固定・8音）では標準版約104%に対し最適化版38.4%、再生API最大待ち6.72msに対し0.530msでした。16音の最適化版は68.1%、最大0.477msです。比較後は元のondemandへ戻し、ゲーム起動時のCPU設定は変更していません。

## 検査

- 実際のDirectSound APIを使用した30条件が成功。8/16bit、モノラル／ステレオ、floatステレオ、11,025～96,000Hz、キャッシュ対象外の比率、再生中の周波数変更、複製・元バッファ解放、ループ／非ループ終了を含みます。
- 数値モデルによる係数比較を実施。元実装の位相計算の丸めとの差があるため、完全一致とはしていません。
- Wineのロードログとプロセスのマッピングで、試験対象DLLを実際に読み込んでいることを確認。
- ユーザーがCOMETで、爆発音が重なる場面の音飛び・引っかかりが解消し、音程・効果音も問題ないことを確認しました。
- GEO3の全体魔法を含む、すべてのタイトル・場面での改善を保証する段階ではありません。

元ソース: https://github.com/wine-mirror/wine/tree/wine-10.0/dlls/dsound 。改変対象はWineのLGPL-2.1-or-laterコードです。各ソースの著作権表示とライセンスを保持します。


## 配置と切り戻し

GUI・CLIに同梱した `dsound.dll` を転送し、共通Wine環境の `syswow64/dsound.dll` から使います。更新した各タイトルは既定で `dsound=n,b` を指定します。Microsoft製DLLは使用しません。ゲームとセーブは変更しません。旧版で転送したゲームは新版ツールで同じ配置IDへ再転送すると更新できます。

本体へSSH接続し、ゲームを終了してから次の設定を置くと、更新済みの全タイトルでWine標準版へ切り戻せます。

```sh
printf 'builtin\n' > /mnt/plumos/ports-runtime/.shared/wine10/audio-backend
```

`builtin` を `optimized` に変えるか、この設定ファイルを削除すると最適化版へ戻ります。どちらも次回のゲーム起動から反映されます。

## ビルドと対応ソース

WindowsのPython 3.11以上とDocker DesktopのLinuxコンテナー環境を使用します。

```powershell
python scripts/build_dsound.py
```

`runtime/audio-source.json` にあるWine 10.0のソースアーカイブをSHA-256で検査し、公開パッチを適用します。AMD64コンテナーでi386用PEコンパイラーへ `-O3 -msse2 -mfpmath=sse` を指定します。ホストのCFLAGS書き換えには依存しません。生成DLL・入力のハッシュとビルド条件を `bld/win32/dsound.json` に記録します。

Wineのbuiltin識別文字列だけを変更して、この改変版が外部PEモジュールとして実際に読み込まれるようにしています。変更元の共有Wineキャッシュは書き換えません。ロードログの `dsound.dll ... native` とDLLのハッシュを検査します。

通常のWindowsビルドもこの処理を呼び、入力と生成DLLのハッシュが一致すれば既存ビルドを再利用します。配布物の `licenses/Wine-dsound` にライセンス・変更パッチ・ビルド情報を含めます。リリースの `*-dsound-source.tar.gz` は、検査した公式ソースそのものとパッチ・ビルド手順・診断ソースをまとめた対応ソースです。展開した場所で上記コマンドを実行できます。
