# 動作確認

対象：PlumOS V90S V2、AArch64、Linux 4.9.191、640×480。

既存の手動構築環境では、以下を順に確認しています。

1. Box64でLinux x86-64プログラムを実行。
2. Wine WoW64でWin32コンソールとGDIウィンドウを表示。
3. DirectDraw 640×480・8bitのサーフェス・パレット・Blt成功。
4. JUMP3のタイトル・本編会話・画面・操作を実機で確認。
5. MSゴシックで会話4行、Aで左クリック、OPL3の音源をユーザーが確認。
6. MIDI受信枠2000、イベント欠落0。サステイン中のAll Notes Off・All Sound Off・GMリセットで波形が無音になる自己検査に成功。

転送ツールの検証（2026-10-23）：

- 公開用DockerfileからARM64ランタイムをビルド。Box64のライセンスとWine用Xcursorライブラリを同梱。
- OPL3音声生成と、サステイン中のAll Notes Off・All Sound Off・GMリセットの消音検査に成功。
- Windows GUI・CLIのEXEを生成し、GUIの初期化・リソース読込・レイアウト検査に成功。
- 生成したCLI EXEから実機へSSH接続し、CPU・空き容量・読み取り専用状態を取得。
- 12件の単体検査に成功。所有ゲームからのパッチ生成・原本保持、ランタイムに私有ファイルがないこと、アーカイブのパス・リンク・重複拒否、日本語設定で無関係なレジストリ値を保持する検査を含む。
- CLI EXEによる新規転送と本体上の `BOX64_LINUX_OK` を確認。
- 空のWine prefixから初期化し、ゲームのタイトル表示まで確認。初回環境作成は本体で数分必要。
- マウス押下・解放がゲーム内部の状態へ届き、「はじめから」で本編の導入へ進むことを確認。
- 会話用フォント寸法22×16、マウスフック登録成功、MIDI受信枠2000・ピーク1040・欠落0を確認。
- 最終CLI EXEで既存テスト環境を更新し、再起動に成功。転送元のSaveData内の同名ファイルを別内容へ変更しても、本体の既存内容が保持されることを確認。
- 日本語ロケールを指定したWin32検査で `WINDOWS_ACP=932 SYSTEM_LCID=1041 USER_LCID=1041` を確認。
- 最終EXEのGUI初期化と12件の単体検査を再確認。検証専用環境のセーブをPCの非公開領域へ退避後、その環境だけを削除。既存JUMP3環境を保持し、本体のext4空き容量2.3GBを確認。

生成ログはGit対象外の `bld/` に保存します。ゲーム本体・画面画像・資格情報は公開テストfixtureへ含めません。

汎用転送への変更（2026-10-23）：

- GUIの大きな見出しと固定タイトル選択を削除。フォルダー内の32bit EXEを選択し、1件なら自動選択する方式へ変更。
- 既知のJUMP3原本は従来の固有修正を維持。それ以外は登録不要で共通環境へ転送し、命令列が一致するマウスフックだけ共通修正。
- FLOAT（フロートランドのおとぎばなし）の原本を変更せず、専用配置 `float-tool-test` へ転送。Box64検査、空のWine prefixからの初回起動、タイトル表示、左クリックによる画面遷移、日本語会話表示、MIDIイベント受信を確認。
- FLOATの表示・操作・音が動いていることをユーザーが実機で確認。
- 17件の検査に成功。固定アドレスに依存しない共通修正、対象外callbackの無変更、使用中のコード追加領域の拒否、複数EXE時の選択要求、FLOATの転送内容と原本保持を追加検証。
- 新しいGUIでFLOAT.EXEの自動選択、生成EXEで初期化成功と見出し削除後のレイアウト寸法を確認。

未検証範囲：JUMP3・FLOAT以外のタイトル、全ミニゲーム、クリアまでの長時間プレイ、すべてのセーブ／ロード操作。

電源メニュー修正（2026-10-23）：

- 不具合時、fbbridgeがPlumOSの電源オーバーレイからSIGSTOPを受け、停止中もevdevの排他取得を保持していることを確認。
- 排他取得を削除し、メニューロックとSIGCONTで入力・描画を抑止／再開。再開時はイベントキューとマウス・キー・移動状態をリセット。
- FLOATの検証環境へ修正版を反映。ゲーム実行中に別のevdevクライアントから短時間の排他取得・解放が成功し、入力を独占しないことを確認。
- 実機ログで電源メニューのsleep選択、fbbridgeの停止・再開、POWER_MENU=1から0への復帰、その後の本体入力を確認。
- 既存JUMP3実機環境には今回のバイナリ置換を行っていません。配布ランタイムには共通修正を反映。

ボタン設定と既存環境の更新（2026-10-23）：

- 左クリックをB、右クリックをAへ変更。YとR2のいずれかを保持するとカーソル2倍速。両方を押した後、片方だけ離しても加速を維持。
- ユーザーの上書き承認後、既存JUMP3環境にも汎用起動設定・電源メニュー修正・新しいボタン設定を転送。Bクリック・Y加速をユーザーが実機で確認。
- 転送前に両ゲームの既存データのハッシュ一覧を保存。JUMP3はSaveDataを転送対象から除外して保持。起動後にゲームが更新したSaveData内の1ファイル以外は一致。
- 同一ランタイムの再利用処理を追加。ファイル内容・モード・リンク先・構成が一致する場合、既存Wineなどをそのまま使用し、不要な重複バックアップを作らない。
- 19件の検査と、最終GUI EXEの初期化に成功。
- 最終CLI EXEから既存FLOAT環境も上書きし、Wineとlicensesの再利用・Box64検査・起動に成功。既存データ279ファイルはハッシュがすべて一致し、両ゲームのfbbridgeが最新バイナリと一致することを確認。

表示高速化（2026-10-23）：

- 従来の約16.8fpsから、待機方式・コピー処理の修正により約59.7fpsの画面転送へ改善。
- X11共有メモリーで取得時間を約8msから約1.8msへ短縮。実ゲームでも転送約60fpsを確認。
- 共有メモリー・従来取得・MIT-SHM拡張が無いXvfbでの自動フォールバックを各64フレーム検査し成功。
- PowerVR GE8300でEGL/OpenGL ESのオフスクリーン描画を確認。今回のゲーム表示はCPU転送の改善で約60fpsに達したため、GPU表示経路は採用していません。
- ユーザーがFLOATの滑らかさ改善、Bクリック、Y/R2加速、電源メニュー復帰を実機で確認。非起動のJUMP3側も旧版を退避して同じ高速化バイナリへ更新。
- 詳細と再検査方法は [PERFORMANCE.md](PERFORMANCE.md) を参照。

コア分散・音源比較とダブルバッファ（2026-10-23）：

- 音源・fbbridge・Xvfb・Wineが独立プロセスで4コアへ分散できることを確認。短時間測定で1コア換算の使用率は音源13.2%、fbbridge15.0%、Xvfb15.2%、FLOAT112.2%。コア固定は追加していません。
- 同一libADLMIDI 1.5.1・1チップ・12音・44.1kHzのオフライン合成でDOSBoxは3.67%、Nukedは23.18%の1コア相当負荷。現行のDOSBox音源設定は維持。
- 本体は640×480の表示ページを2枚使用可能。VSync待ちioctlは即時復帰でしたが、垂直帰線時のページ切替は20回連続で約16.8～16.9ms周期の待機を確認。
- 非表示ページへの描画とページ切替を実装。FLOATで約59fpsを維持し、ユーザーが表示・B/Y/R2操作・電源メニュー復帰に問題ないことを確認。
- JUMP3の非起動を確認し、旧版を退避して同じブリッジを反映。
