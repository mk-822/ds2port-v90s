# 動作確認

対象：PlumOS V90S V2、AArch64、Linux 4.9.191、640×480。

既存の手動構築環境では、以下を順に確認しています。

1. Box64でLinux x86-64プログラムを実行。
2. Wine WoW64でWin32コンソールとGDIウィンドウを表示。
3. DirectDraw 640×480・8bitのサーフェス・パレット・Blt成功。
4. JUMP3のタイトル・本編会話・画面・操作を実機で確認。
5. MSゴシックで会話4行、Aで左クリック、OPL3の音源をユーザーが確認。
6. MIDI受信枠2000、イベント欠落0。サステイン中のAll Notes Off・All Sound Off・GMリセットで波形が無音になる自己検査に成功。

OPMONと容量不足対策（2026-10-23）：

- OPMON（ac_mon.exe）は転送成功後の初回Wine環境作成でext4空き容量が0になり、レジストリ保存と日本語設定に失敗していた。
- 管理対象3ゲームのWineについて、内容・モード・所有者が一致する2705ファイル、各670,527,873バイトをハードリンク共有化。約1.3GBを回復し、設定・ゲーム・セーブ・各prefixは個別のまま保持。
- 不完全なOPMON prefixをバックアップへ退避して初期化を再実行。ユーザーがOPMONの画面・操作・BGMと、Ports一覧の更新を確認。
- 初回Wine環境の増加分を640MiB、OS用余裕を128MiBとして転送前の空き容量判定へ加算。途中作成のprefixも不足分を予約し、起動時にも容量を確認。
- 新規転送では他の管理対象ゲームと同一のWineバイナリを共有。内容・モードの不一致は共有せず、更新は置換するため他のゲームへ波及しない。
- 別途FATのクラスターチェーン不整合と読み取り専用化を検出。ゲームと設定をPCへ退避し、ユーザー承認後に全FATマウントを解除して標準fsckで修復。アンマウント状態で再検査が終了コード0。
- 生成設定を再作成し、ゲーム・セーブ577ファイルすべてのSHA-256が修復前と一致することを確認。マウントとPorts画面を復元。修復後のext4空き容量は約738MiB。
- Windowsで25件の検査中24件成功、Linux専用の1件はスキップ。Linux ARM64で共有・更新分離・内容/モード差・リンク逸脱拒否・容量予約の4件に成功。生成GUI EXEの起動検査にも成功。
